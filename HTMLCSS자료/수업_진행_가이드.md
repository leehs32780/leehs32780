## 2. 이 시간이 어떻게 나온 숫자인지

지어낸 숫자가 아니라 **실제로 센 항목 수 × 항목당 시간**입니다.
학원 속도가 다르면 아래 항목당 시간만 바꿔서 다시 계산하시면 됩니다.

| 항목 | 잡은 시간 | 근거 |
|---|---|---|
| 개념 섹션 1개 | 4분 | 설명 + 브라우저에서 결과 확인 |
| ✏️ 직접 해보기 1개 | 3분 | 고치고 → 저장하고 → 새로고침 |
| 연습문제 (기본) | 5분 | |
| 연습문제 `[응용]` | 8분 | |
| 연습문제 `[도전]` | 12분 | |
| `[확인]` 문항 | 3분 | 일부러 틀린 코드를 찾아 고치기 |
| 14단원 종합 1단계 | 12분 | 사실상 미니 프로젝트 단계 |

> 예를 들어 "개념 섹션 하나에 6분은 걸린다" 싶으면 전체가 76시간 → 91시간이 됩니다.

**JS자료(68시간)보다 8시간 깁니다.** HTML/CSS 는 화면을 눈으로 확인하는 왕복이 매번 들어가서
같은 섹션 수라도 실제로 더 느립니다. 그 왕복 시간이 위 표의 "4분"에 들어 있습니다.

## 5. 06단원 → 07단원 전환이 이 과정의 고비입니다

01~06단원은 "글에 이름표를 붙이는" 일이라 결과가 밋밋합니다.
특히 **06단원 시맨틱 태그는 화면을 전혀 바꾸지 않습니다.** 학생이 여기서 가장 많이 지칩니다.

대응 방법 두 가지입니다.

1. **01단원 첫 시간에 `14_종합_연습/종합04_반응형_랜딩페이지_정답.html` 을 열어 보여 주세요.**
   "6일 뒤부터 이걸 만들기 시작합니다" 를 눈으로 심어 두면 06단원을 버팁니다.
2. **06단원 마지막 시간에 07단원 개념01 을 15분만 미리 보여 주세요.**
   같은 HTML 에 CSS 를 붙였을 때 얼마나 달라지는지 보고 주말을 넘기게 하는 편이 좋습니다.

## 7. 수업 전 점검표

- [ ] 학생 PC 에 **크롬(또는 엣지)** 과 **VS Code** 가 깔려 있는가
- [ ] 학생이 **화면을 반으로 나눠** VS Code 와 브라우저를 동시에 띄울 수 있는가
- [ ] `.html` 더블클릭이 **VS Code 가 아니라 브라우저**로 열리는가
      (아니면 우클릭 → 연결 프로그램 → 크롬 → "항상 이 앱으로 열기")
- [ ] **`F12`** 가 눌리는가 (노트북은 `Fn`+`F12` 인 경우가 있습니다)
- [ ] 자료 폴더를 **통째로** 복사했는가 — `공통.css` 와 `이미지/` 가 빠지면 화면이 깨집니다
- [ ] 학생에게 **폴더를 한 벌 백업**해 두게 했는가 (마음껏 고쳐 봐야 늡니다)

**인터넷은 필요 없습니다.** 그림도 전부 폴더 안에 들어 있습니다.

## 8. 단원별 필수 시연 (여기서 학생이 반드시 막힙니다)

| 단원 | 반드시 직접 보여 줄 것 |
|---|---|
| 01 | **저장(Ctrl+S) → 새로고침(F5)** 세 단계. 이걸 안 하면 이후 전 단원이 막힙니다 |
| 01 | HTML 은 틀려도 **에러가 안 난다**는 것. 닫는 태그를 지워 보이세요 |
| 02 | `h4` 는 문단과 크기가 같고 `h6` 은 **더 작다** — "제목 = 큰 글씨" 오해를 여기서 깨세요 |
| 03 | `colspan` 을 쓰면 그 행의 `td` 를 **하나 줄여야** 한다는 것 |
| 04 | **경로**. 폴더를 실제로 열어 놓고 `../` 가 어디로 가는지 손으로 짚어 주세요 |
| 05 | `label` 의 글자를 눌러 **체크박스가 켜지는 것**. `for`↔`id` 가 연결됐다는 증거입니다 |
| 05 | `radio` 는 **`name` 이 같아야** 하나만 골라진다는 것 |
| 06 | 시맨틱 태그로 바꿔도 **화면이 안 바뀐다**는 것. 이걸 미리 말 안 하면 배신감을 느낍니다 |
| 07 | 속성 이름을 일부러 틀려서 **그 줄만 조용히 버려지는 것** |
| 08 | **F12 → Styles 에서 취소선 그어진 규칙.** 명시도를 눈으로 보는 유일한 방법입니다 |
| 09 | `em` 을 중첩하면 글자가 **곱해져서 커지는 것** |
| 10 | **F12 → Computed 의 박스 모델 그림.** 이 단원은 이것 없이는 안 됩니다 |
| 10 | `margin` 겹침 — 40 과 30 을 주면 70 이 아니라 **40** 이 되는 것 |
| 11 | `inline` 요소에 `width` 를 줘도 **안 먹는 것** |
| 12 | `flex-direction: column` 으로 바꾸면 `justify-content` 와 `align-items` 가 **뒤바뀌는 것** |
| 13 | **`Ctrl+Shift+M`** 으로 화면 폭을 줄여 카드가 접히는 것 |
| 13 | `viewport` meta 를 지우면 휴대폰에서 어떻게 되는지 |

## 9. 이 자료의 특이한 점 (미리 아셔야 할 것)

**설명이 두 군데에 있습니다.** 브라우저 화면에는 섹션 제목·요약·실제 결과가 보이고,
**자세한 설명은 소스의 주석**에 있습니다. 학생이 브라우저만 보면 절반만 보는 것입니다.
첫 시간에 "VS Code 와 브라우저를 나란히" 를 반드시 습관 들이세요.

**`공통.css` 는 자료 껍데기입니다.** 노란 안내 상자, 점선 데모 상자를 만듭니다.
`doc-` 으로 시작하는 클래스가 전부 그것입니다. **학생이 만들 클래스와 겹치지 않게** 설계했으니
"이건 우리가 배우는 게 아니다" 라고만 정리해 주시면 됩니다. 고치면 모든 파일이 깨집니다.

**파일 맨 아래 `검증` 블록**은 자료가 스스로 틀리지 않았는지 검사하는 장치입니다.
자료에 적힌 색·크기·위치는 전부 **진짜 크롬으로 열어서 잰 값**입니다.
학생에게는 "넘어가세요" 라고 하시면 됩니다.

**01~06단원에는 CSS 가 한 줄도 없습니다.** 일부러 그렇게 했습니다.
"HTML 은 무엇인가, CSS 는 어떻게 보이는가" 를 몸으로 갈라 놓기 위해서입니다.
그래서 06단원까지는 화면이 계속 밋밋합니다(5절 참고).

## 10. 자주 받는 질문

**"코드를 고쳤는데 화면이 안 바뀌어요"**
→ 1순위 저장 안 함, 2순위 새로고침 안 함. 3순위는 다른 파일을 고친 것입니다.

**"아무 일도 안 일어나요"**
→ HTML/CSS 는 에러를 안 냅니다. F12 → Elements 에서 그 요소를 찾아
Styles 에 내가 쓴 규칙이 있는지부터 보게 하세요. 없으면 **선택자가 안 맞은 것**,
있는데 취소선이면 **명시도에 진 것**(08단원)입니다.

**"제 화면은 자료랑 색이 조금 달라요"**
→ 글꼴 때문입니다. 맑은 고딕이 없는 PC 면 글자 폭이 달라져 줄바꿈 위치가 바뀝니다.
색·크기는 같아야 합니다. 다르면 오타입니다.

**"이거 실무에서도 이렇게 쓰나요"**
→ 10단원 `box-sizing`, 12단원 flex, 13단원 미디어쿼리는 그대로 씁니다.
11단원 `float` 은 요즘 배치용으로 안 씁니다(자료에도 그렇게 적혀 있습니다).
`table` 로 화면을 배치하던 방식도 지금은 안 씁니다(03단원에 경고가 있습니다).
