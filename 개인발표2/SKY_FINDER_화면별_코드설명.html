SKY FINDER 화면별 코드 설명

인기 여행지 팝업을 제외한 발표 추천 기능 정리

SKY FINDER는 출발지와 도착지, 날짜를 입력해 항공편을 비교하고, 가는 편과 오는 편 선택부터 결제 PIN 확인, 예약 저장과 취소까지 체험할 수 있도록 만든 React 기반 항공권 검색 웹앱입니다.

1. 전체 화면과 추천 발표 흐름

  1. 출발 공항을 선택하고 달라지는 도착지 목록 확인
  2. 왕복 날짜를 입력하고 항공권 검색
  3. 가는 편과 오는 편을 차례로 선택
  4. 탑승객 정보와 결제수단 입력
  5. 6자리 결제 PIN 확인 후 예약 완료
  6. 헤더의 내 예약에서 예약 조회 및 취소

2. 출발지에 따라 달라지는 도착지

App.jsx 200~227줄, 824~923줄 / appData.js 396~425줄

화면: 출발 공항을 선택하기 전에는 도착지 선택창이 비활성화됩니다. 출발 공항을 선택하면 실제 연결된 목적지만 국내와 국가별 그룹으로 나타납니다.

코드: getArrivalCountries()가 선택한 공항의 노선을 국내와 국제선으로 분류합니다. 출발지가 변경되면 이전 도착지를 빈 값으로 초기화해 잘못된 조합을 방지합니다.

발표 멘트: “출발 공항에 따라 갈 수 있는 도착지가 달라지도록 구현했습니다. 출발지를 바꾸면 기존 도착지를 초기화하여 연결되지 않은 노선을 검색하지 못하게 했습니다.”

강조할 개념: useState, useMemo, 제어 컴포넌트, 배열 분류, 조건부 비활성화

3. 항공권 검색과 로딩 상태

App.jsx 229~263줄, 924~1018줄

화면: 검색 버튼을 누르면 비행기 아이콘과 “최적의 항공편을 찾고 있어요”라는 로딩 화면이 표시되고, 완료 후 항공편 카드가 나타납니다.

코드: 검색 전 출발지, 도착지와 날짜가 모두 입력되었는지 검사합니다. 검색 중에는 버튼을 비활성화하고 기존 결과를 초기화합니다. 발표용으로 3초 뒤 결과가 나타나도록 구성했습니다.

발표 멘트: “입력값 검증, 로딩, 성공 결과라는 세 가지 사용자 상태를 나누었습니다. 검색 중 중복 클릭을 막기 위해 버튼도 비활성화했습니다.”

강조할 개념: 폼 검증, 이벤트 처리, 로딩 UX, 조건부 렌더링, 타이머 정리

4. 노선별 항공편 생성

appData.js 188~339줄, 341~394줄, 427~500줄

범위역할
188~216줄공항별 IANA 시간대
217~235줄목적지별 비행시간
237~280줄노선 기준 가격과 항공사별 가격 비율
282~339줄노선별 운항 가능한 항공사 제한
341~394줄출발 현지 시각을 UTC로 바꾸고 도착 현지 시각 계산
427~500줄항공사, 편명, 시간, 좌석과 가격을 포함한 결과 생성

화면: 검색 결과 카드에는 항공사, 편명, 출발·도착 시간, 비행시간, 남은 좌석과 가격이 표시됩니다.

발표 멘트: “완전히 무작위로 표시하지 않고 노선별 운항사, 기준 가격, 비행시간과 시차를 조합했습니다. 미국이나 유럽 노선은 현지 시간과 도착 날짜가 달라지는 부분도 계산합니다.”

강조할 개념: 데이터와 UI 분리, map, 시간대 변환, 가격 계산, 재사용 가능한 함수

5. 편도와 왕복 선택 흐름

App.jsx 265~289줄, 947~1100줄

화면: 편도는 항공편을 선택하면 예약 창이 열립니다. 왕복은 먼저 가는 편을 선택한 뒤 오는 편 목록이 새로 나타납니다.

코드: 왕복에서는 출발지와 도착지를 서로 바꾸고 귀국일을 새로운 출발일로 사용하여 오는 편을 생성합니다. 생성 후 오는 편 영역으로 부드럽게 스크롤합니다.

발표 멘트: “여행 유형에 따라 같은 선택 버튼이 다른 흐름으로 동작합니다. 왕복은 선택한 가는 편을 상태에 저장하고 역방향 노선을 다시 계산합니다.”

강조할 개념: 상태 기반 화면 전환, 객체 전개 문법, 분기 처리, DOM 스크롤

6. 결제 PIN과 예약 저장

App.jsx 291~360줄 / AppOverlays.jsx 472~715줄

화면: 항공편을 선택하면 탑승객 이름, 전화번호, 이메일과 결제수단을 입력하는 모달이 열립니다. 다음 단계에서 6자리 PIN을 입력하면 결제 완료 화면과 예약번호가 표시됩니다.

코드: PIN 등록 여부와 일치 여부를 확인하고, 성공하면 항공편·탑승객·결제 정보를 하나의 예약 객체로 만듭니다. 예약번호는 SF와 현재 시간을 조합하며 왕복 가격은 가는 편과 오는 편을 합산합니다.

발표 멘트: “검색 결과가 결제로 끝나는 것이 아니라 탑승객 정보와 결제 정보를 예약 객체로 묶고, 예약 완료 화면까지 하나의 사용자 흐름으로 연결했습니다.”

주의: 실제 결제가 아닌 발표용 테스트 기능이며, 실제 서비스에서는 결제사 API와 서버 검증이 필요합니다.

7. 내 예약 조회와 취소

App.jsx 680~697줄 / MyBookingsModal.jsx 1~101줄

화면: 헤더의 내 예약을 누르면 현재 사용자의 예약번호, 항공편, 탑승객과 결제 정보가 나타납니다. 취소 버튼으로 선택한 예약만 삭제할 수 있습니다.

코드: 로그인한 사용자의 ID와 예약의 ownerId를 비교해 본인의 예약만 보여줍니다. 취소 시 React 상태와 localStorage를 함께 변경합니다.

발표 멘트: “사용자별로 예약을 필터링하고, 취소하면 화면과 브라우저 저장 데이터가 동시에 갱신되도록 했습니다.”

8. 로그인과 회원가입

App.jsx 363~474줄 / AppOverlays.jsx 84~188줄

화면: 하나의 인증 팝업에서 로그인, 회원가입, 아이디 찾기와 비밀번호 재설정 화면이 전환됩니다.

코드: 회원가입 시 아이디 중복, 비밀번호 길이와 확인값을 검사합니다. 로그인 성공 시 사용자 정보를 저장해 새로고침 후에도 상태를 복원합니다.

발표 멘트: “여러 팝업을 따로 만들지 않고 인증 모드 상태에 따라 필요한 폼만 조건부로 렌더링했습니다.”

주의: localStorage에 비밀번호를 저장하는 방식은 시연용입니다. 실제 서비스에서는 서버, 비밀번호 해시와 인증 토큰을 사용해야 합니다.

9. 자동 전환 여행 영상

App.jsx 801~815줄

화면: 메인 화면 오른쪽 위에서 여행 영상이 자동 재생되며 약 4초마다 다음 장면으로 바뀝니다.

코드: 영상 시간이 4초 이상이면 인덱스를 증가시키고, 나머지 연산자로 마지막 영상 뒤에 첫 영상으로 돌아갑니다.

발표 멘트: “영상 배열의 인덱스를 상태로 관리해 짧은 여행 장면이 계속 순환하도록 만들었습니다.”

11. 마무리 멘트

“SKY FINDER에서는 React의 상태 관리와 조건부 렌더링을 이용해 검색, 왕복 항공편 선택, 결제와 예약 조회까지 하나의 흐름으로 연결했습니다. 현재 데이터와 결제는 발표용이지만, 앞으로 실제 항공편 API와 백엔드를 연결하면 실제 서비스 형태로 발전시킬 수 있습니다.”
